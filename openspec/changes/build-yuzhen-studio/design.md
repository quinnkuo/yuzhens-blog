## 背景

当前仓库里主要是 flomo 导出内容，包含日记性质的私人笔记和媒体文件，但还没有网站项目。目标网站是 **Yuzhen's Blog**，它是一个面向读者的个人站，用来展示公开文章和个人作品。

第一版应该优先搭建一个稳定、可部署、可逐步填充内容的静态网站基础。网站定位围绕这句话展开：

> 我持续记录一个普通人在生活、工作和 AI 时代里的变化。

## 目标 / 非目标

**目标：**

- 搭建一个可以部署到 GitHub Pages 的静态个人网站。
- 建立公开信息架构：首页、文章、主题、作品、关于。
- 支持公开内容类型：文章、主题、作品、精选短札。
- 允许先放少量真实样本内容，后续再逐步扩展。
- 原始 flomo 和私人日记内容与公开内容分开管理。
- 提供适合中文长文阅读的视觉、排版和导航基础。

**非目标：**

- 不做 flomo 全自动导入。
- 不做公众号文章全自动同步。
- 不公开原始日记归档。
- 不做评论、登录、私密区域、邮件订阅、数据分析或复杂搜索。
- 不引入 CMS 或数据库后台。

## 技术决策

### 使用 Astro 作为静态网站框架

第一版使用 Astro。它适合静态输出、Markdown/MDX 内容、内容集合和组件化布局，同时不会把一个以写作和作品展示为主的网站做得过重。

考虑过的替代方案：

- Jekyll：和 GitHub Pages 很搭，但现代组件布局和内容模型不如 Astro 灵活。
- 纯 HTML/CSS：部署最简单，但文章列表、详情页、作品页和后续内容增长会很难维护。
- React/Vite：足够灵活，但对一个主要是静态内容的网站来说偏重。

### 使用“精选发布”内容模型，而不是直接导入原始内容

公开内容会放在明确的内容目录里，例如文章、主题、作品、精选短札。原始 flomo 导出不会直接进入公开内容目录。这样可以保护隐私，也强化编辑逻辑：只有经过筛选、编辑、补充公开元数据的内容才发布。

### 首页采用编辑型入口，而不是纯时间线

首页先展示 Yuzhen's Blog 的身份和定位，然后展示精选文章、长期主题、作品和最近更新。纯时间线容易让新读者直接进入碎片流，看不出这个站点的中心。

### 主题是读者路径，不是原始标签

主题页用于组织“生活里的变化”“工作里的变化”“AI 时代里的变化”“写作与创作”等长期方向。以后可以增加标签系统，但第一版更适合先用少量清晰主题，让读者快速理解网站结构。

### 通过静态构建发布到 GitHub Pages

项目会提供构建命令和 GitHub Pages 发布方式。等仓库关联到 GitHub 后，可以通过 GitHub Actions 或 GitHub Pages 的静态产物部署流程上线。

## 风险 / 取舍

- **风险：上线时内容太少** -> 先放少量代表性样本内容，并为内容较少的栏目设计清楚的空状态。
- **风险：私人日记内容误入公开构建** -> 原始导出不放入公开内容目录，公开内容必须有明确 frontmatter 元数据。
- **风险：复合型创作者定位显得分散** -> 首页主题保持克制，用核心副标题把内容收束起来。
- **风险：过早期待公众号自动同步** -> 第一版保留来源链接字段，但自动化同步留到后续独立变更。
- **风险：GitHub Pages 路径配置出错** -> 使用静态输出，并在实现时处理好项目页可能需要的 base path。
